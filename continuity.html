Continuity — how this system works, and how to rebuild it somewhere else

A plain inventory of the pieces, the data, and the order to put them back together. No passwords, keys, or addresses live on this page — on purpose.

What the system is

One automated betting pipeline. Game picks are posted in a Discord channel (the Alpha GOAL feed). A program on a cloud server reads each pick, and when the game's betting window opens late in the second half, it drives an Android phone — through the phone's own Bet365 app — to watch the price and place one bet per game, only when the price is at or above the agreed minimum of 1.65. Every bet, skip, and balance change is written into a set of books on the server, and this website is a read-only window into those books.

The pieces

Discord server — “Danny & Imran's Bot”. The front door. Picks arrive in the signals channel; a status channel carries the living record; a logs channel carries the running story in plain words; a reports channel carries summaries. The betting program reads the picks channel and writes to the others.

Cloud server (Hetzner, 8 GB of memory). The brain. It runs these services:

  • betbot — the betting program itself: reads picks, keeps the queue, watches prices in each window, places bets through the phone, settles results, and keeps the books.
  • droidline-serve and s22shadow-bridge — the phone bridge: the two halves of the connection that let the server see the phone's screen and tap it.
  • janitor-watcher and janitor-ctl — the watchdog pair: they notice a stuck or dead piece and restart it.
  • betbot-responder — automatic recovery for the phone connection when it drops.
  • betbot-dashboard-live — the read-only exporter: once a minute it reads the books (never writes them) and publishes the website's data file.
  • A local AI model (Ollama running a model called betbot-qwen) — reads the free-text picks posts in Discord and turns them into structured games for the queue. It runs entirely on the server; no outside AI service is involved.

The Android phone (Samsung S22). The hands. It runs the Bet365 app, signed in to the betting account, plus a small automation app (the Executor) that the bridge talks to. The phone places every bet through the real app — there is no other betting connection. The phone must stay charged, unlocked, and signed in; if it sleeps or signs out, the system can heal a sign-out but cannot wake a sleeping phone.

The books (on the server). A database file holding every bet, the queue, and the bankroll, plus a plain-text event log and a small health file. These files are the system's memory — everything else can be rebuilt, these must be carried over.

This website. Two GitHub repositories: one holds the site itself (published with GitHub Pages), the other holds only the data file the exporter publishes each minute. The site never talks to the server or the phone directly.

A private network (Tailscale) joins the server, the phone, and the operator's own computer, so the pieces can reach each other without being open to the public internet.

Save this first — the data that matters

  1. The books database — every bet ever placed, the current queue, the bankroll, and the ladder position. Without it, the record starts over.
  2. The event log — the blow-by-blow history the post-mortems and this site's game journeys are built from.
  3. The rules and settings files — the strategy numbers (the 1.65 minimum, the staking ladder), the channel list, and the read positions that tell the intake where it stopped reading Discord.
  4. The health file — the last known phone and balance readings.

Passwords and tokens are never part of the move. Nothing on this page contains one, and none should ever be written into a file that travels. On a new home, the owner signs in to each account again and enters each secret through that service's own secure setup, one at a time.

Accounts a rebuild needs

  • The Discord server and its bot (the picks feed lives there).
  • The cloud server account (the brain's home).
  • The GitHub account holding the two dashboard repositories.
  • The Bet365 account, signed in on the phone.
  • The private network account that joins server, phone, and operator computer.

Rebuild order

  1. Preserve the data first. Copy the books, the event log, the rules/settings, and the health file off the old server before anything is switched off.
  2. Stand up the new server and install the services listed above — with the betting service itself left off.
  3. Install the local AI model and confirm it loads and answers on the new server (it needs most of the server's memory; keep the server's scratch space on disk, not in memory).
  4. Restore the books and settings into the new server's program folder.
  5. Reconnect Discord in read-only fashion and confirm a fresh picks post is read and queued correctly before trusting it.
  6. Reconnect the phone path (bridge + Executor), then verify by eye: a balance read through the bridge matches the balance shown in the app.
  7. Point the exporter at the data repository, deploy the website, and confirm the site shows the same balance, record, and queue as the books.
  8. Only then turn betting on — and only after the balance has been verified two independent ways.
  9. Keep the old system off. Two copies of the betting program running at once would double-place bets. A move is finished when the old home is stopped for good.

Rules that travel with the system

  • One betting instance, ever. One program places bets; everything else is read-only or recovery.
  • The price minimum is 1.65, under every line, with no upper limit. Stakes come from the ladder, which is recalculated from the current bankroll after every change.
  • A bet counts as real only when there is a placement receipt and a matching movement in the balance. A row in the books alone is never proof.
  • The next bet is staked only after the previous one is settled and booked, with two agreeing balance readings.
  • If a second-half goal is scored before a game's window opens, the game is skipped — judged from a halftime score snapshot taken while the game was being staged.
